已于2026-09-15部署至 https://prod.huiyuanxp.com ，版本 `intake-v2-20260915T083433Z`。本轮测试、保留失败及回滚记录见交接与部署文档。

本实现对应用户授权的 Ticket03/04/05/09 扩展，不是新 Ticket17，也不代表全屋几何、墙体编辑或 Ticket14 的整包导出已完成。实施与验收状态以 `docs/handoffs/AGENT-INTAKE-V2.md` 和 `CURRENT.md` 为准。

## 用户操作

工作台 → **聊聊你的家**。文字区下方固定放置 **添加、语音、资料、发送**，无需先打开另一个媒体面板才能录音。添加菜单包含照片/参考图、文档/户型资料、WAV音频；可以拖放或粘贴文件。当前待引用附件带预览、上传/读取/失败状态。移除本轮附件只取消引用，不会删除项目中的原件。

点击语音、允许麦克风、录制后停止：浏览器真实编码，并归一化为WAV；服务器转写后放进可编辑文字输入框。用户检查后再发送，不把模型转写直接当成已确认需求。取消、收起聊天或权限请求后离开会终止录音并释放麦克风；已停止的录音保留原件。最大60秒。当前要求浏览器支持 MediaRecorder `audio/webm`；不支持时明确提示改为上传WAV或文字，不冒充具备所有浏览器的录音能力。这不是电话式实时语音对话或语音朗读。

图片支持PNG/JPEG/WebP；JPEG/WebP会保留原件并归一化为PNG供现有模型处理。现有图片分析提取色调与功能候选，标记来源；点击采用才改变对应字段，不能从外观断言尺寸、承重或材料认证。

文档支持PDF、DOCX、TXT、Markdown、CSV、JSON。PDF读取文字层并保留页码；DOCX读取文字，不执行宏或外部引用。不做OCR、任意户型自动重建或图纸工程校核。扫描件、加密/损坏文档或超过安全处理限额时明确说明未读懂，保留原件，请用户提供重点页图片。复杂表格与图纸布局不保证从纯文字提取中完整保留。

当前配额：单文件5MB，项目总计10个附件/20MB，每轮最多引用6个附件。文档最多50页/40,000提取字符；超长内容明确标记为截断。解析在限内存的worker中进行，12秒超时，同一进程同时最多2个文档解析。附件下载仍须当前业主身份验证。

## 推荐式追问

每轮读取全屋及当前房间已有信息，再选最多两个有价值的未答问题。聊天下方的折叠卡不占满消息阅读区，仍可随时输入或录音。结构是：

| 项 | 行为 |
|---|---|
| A | 有证据时给出预测/推荐方向、理由和来源；无足够证据时标为探索起点。不会预选。 |
| B/C/D | 三个实质不同的替代方向，而不是改写同一句话。 |
| E | 完整自由描述，可补充原因、顾虑或推翻全部选项。 |
| 暂不确定/先跳过/不适用 | 独立于四个方向，不强迫虚构答案；可记录负责人和下一步。 |

预算、尺寸、币种、权限、成员或健康等事实不能随意猜测。此类题目的选项由服务器保持为补充资料的方式，不允许模型写入虚构事实默认值。选择单题只影响该题及明确的旧字段映射，不改变场景，不确认整套方案，更不等于施工许可或安全证明。

原话提取必须逐字来自本轮当前房间的用户消息，保存为“待核对”，不能覆盖已保存的手工值。未知、跳过、不适用和已有待核对回答不会反复追问，用户可在完整问卷中主动修改。附件作者说的话不是业主确认；参考内容中的工具命令、角色指令或链接要求都作为不可信数据处理。

## 60题问卷

从聊天快捷入口 **完整问卷 · 60题** 打开，也可从交付清单返回补充。48道基础题＋12个条件分支的定义在 `packages/contracts/intake.ts`，不是将示例家庭、城市或预算复制成默认值。

覆盖项目目标/范围/授权/共享；居住成员与日常生活；感受、偏好、禁忌与保留物；预算目标、硬上限、币种、口径、时间与分期；逐房间功能、尺寸来源、现状约束、设备、收纳；材料、照明、维护、舒适度；比较取舍、交接、确认范围与满意度；以及婴幼儿、无障碍、宠物、定制、重物、施工中居住、参考媒体和分歧等分支。

全屋题跨房间共享，房间题按真实稳定room ID隔离。界面可筛选、搜索、查看原话提取和显式修改。明确完成数不包括未知、跳过和待核对。离开未保存题目会提示；取消离开后保留本题草稿。聊天窗口内的消息草稿和待引用附件在收起/切回房间时保留，但本轮不承诺未发送草稿跨浏览器刷新、登出或设备同步。

预算范围保留原文，目标与硬上限单独存储；不把范围偷偷取中间值填入旧的“总预算”数值字段。旧侧栏16字段保留兼容，仅明确同义字段（scope/occupants/decision_makers/priorities/currency/budget_scope/timeline/purpose）同步。完整问卷和交付清单是新字段的主要编辑/阅读入口。

## 双受众交付清单

进入 **问卷与交付** 或聊天的 **交付清单**：

**业主理解与预期**呈现听到的目标/感受、全屋功能预期、日常生活场景、参考资料状态、已明确和仍可改变的选择。**设计师需求交接**呈现项目摘要、分房间需求、偏好和原话依据、家具/材料/性能意向、讨论和决策、预算口径、实施阶段、缺口及专业复核事项。

每项交付分“资料已齐备、草案/仍需复核、待补充”。没有提供的测量、没有生成的全屋图、未核实的墙体性质，不能由AI补造为完成。实施顺序是建议的依赖计划，不承诺未经确认的工期或报价。

保存快照后下载JSON或Markdown，固定项目版本和任务书版本。后续需求修改使历史快照过期，但不改写旧内容。当前原生OpenPlan3D重新导入、同版本全屋/细节视图、正式PDF整包仍属于后续交付验收；D10明确为未完成。图片“喜欢哪里/不复制哪里”的信息可由Q15/Q57记录，但逐图区域标注、自动细节图制作和全屋效果图生成不在本实现中。

旧“需求任务书”的基础字段及独立审查入口继续保留；本次新增60题完整内容使用新的“问卷与交付”，不能把旧16字段审查报告当成全部60题已受独立模型审查。

## 共享、确认与保存安全

Q06默认仅本人可见。用户可明确选择摘要（不含原始对话/附件，且排除若干敏感类别），或逐项勾选需求及附件。没有预选的广泛授权，也不会自动发送邮件/链接。共享范围在当前导出中实际过滤，不只是UI标签；授权改变后旧设计师快照拒绝继续导出，须重新生成。下载前仍需本人检查填写文字中的个人信息，不承诺自动脱敏。

现有后端统一事务、owner授权、request_id幂等与expected_version保护继续生效。冲突保留表单草稿，用户核对新值后再次确认。新字段为项目JSON的可选扩展；没有修改原生场景格式、墙体或家具几何。

## Agent工具与上下文

`apps/api/agent-intake-tools.ts` 是实际运行的v2提示词和工具实现，不是仅供未来参考的Prompt：

- `read_consultation`：读取当前授权快照、简化问卷状态、当前房间参考资料及优先引用的本轮附件。
- `record_intake_answer`：逐字记录用户明确说法，待核对，不替代确认。
- `ask_intake_question`：推荐A＋B/C/D；服务器检查题目、证据、作用域、已答状态和重复选项。
- `read_intake_detail` / `read_attachment_excerpt`：读取受限的完整单题回答或附件片段，避免把全部长文无界塞进上下文。

主咨询最多六轮模型调用；仅当缺少真实有效的选择卡时，再执行一次最多两轮调用的专门结构化补全。其他既有Agent保留四轮上限。整个咨询共享90秒超时。保存后的后置检查不以模型正文“已生成”的表述作为证据；补全仍失败时明确更正该表述、保留输入并返回失败状态。新增安全failure_code不暴露配置、凭据或原始provider错误。

## API入口

| 方法 | 路径后缀（前缀 `/api/projects/:id`） | 用途 |
|---|---|---|
| GET | `/intake?room_id=...` | 60题、适用性、现有答案、最多2个当前问题 |
| POST | `/intake/answer` | 单题显式选择/自由填写/未知状态保存 |
| POST | `/documents` | 文档原件和安全文字提取 |
| POST | `/documents/retry` | 使用保留原件重试提取 |
| POST | `/chat` | 文本＋可选attachment_ids，限制当前房间与6个引用 |
| GET | `/delivery?audience=owner|designer` | 实时草稿与真实缺口 |
| POST | `/delivery/snapshots` | 保存固定版本交付快照 |
| GET | `/delivery/snapshots/:snapshot?format=json|md` | 下载受当前授权约束的历史快照 |

媒体上传、分析、转写确认和私有原件下载继续复用原有`/media`接口。交付快照不是自动对外发布接口。
