# 设计师初访提纲（草案，未开展访谈）

状态：仅根据本项目已确认的产品规格整理。没有设计师访谈、用户研究或专业安全验证的完成记录，不得在演示中声称已验证有效。

## 五组问题

1. 居住与决策：谁居住、如何使用房间、谁共同决策？设计师实际先询问哪些信息？多人意见分歧如何记录？
2. 预算与时间：金额、币种、是否含家具/家电/施工/税费、最早开始与目标入住日。预算未知时下一步如何推进，哪些内容不应默认？
3. 空间与改造：可用平面图、现场尺寸、净高、结构条件、改造范围、保留物品。什么信息必须由专业人员现场确认，不能从示意图推定？
4. 风格与生活：色调、材料偏好、功能关键词、参考图片/视频。哪些信息更适合展示样例后让业主选择，而不是直接追问术语？
5. 取舍与确认：预算、收纳、通行、维护、未来变化的优先级。哪些字段可单独确认，哪些必须作为一个约束组审阅？

## 场景分支与验证问题

宝宝房/照护：是否需要随成长调整用途？如何在界面区分一般收纳建议与需要专业复核的家具、通行和施工安全问题？不得把“环保”“零甲醛”等未经证明的说法写成认证。
长辈/行动辅助：如何收集实际辅助需求而不根据年龄擅自假定？哪些通行、设备和施工要求必须转给专业人员？
有限预算：设计师是否同意先保留未知币种/范围，而非自动填一个看似完整的预算？
多人决策：已提供的事实、个人偏好和共同确认应如何分层显示？

## 一次可执行的访谈流程

先介绍原型限制与数据用途，并获得展示案例的同意。使用合成客厅案例，请设计师完成“读取原话 → 修改一个字段 → 采用一个建议 → 查看独立审查”，观察混淆点，不诱导其认可设计。重点询问灰色建议是否可能被误认为已保存，以及目标尺寸是否可能被误认为真实测量。

记录表应包含：参与者角色（可匿名）、日期、同意范围、原话、对应字段/界面、问题严重程度、建议改动、验证状态。未经许可不保存识别信息或客户资料。
