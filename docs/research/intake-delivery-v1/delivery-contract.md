# 双受众交付标准

## 设计师版：让专业人员能接手，而不是让摘要看起来很长

D01 项目摘要：目标、参与者、范围、不做什么、预算口径、时间、当前版本。
D02 分房间需求：活动、人数、频率、物品、动线、优先级、可牺牲项、不能改变的条件。
D03 偏好证据：用户原话、喜欢/不喜欢的具体视觉元素、意义与理由、媒体来源/标注位置。
D04 家具材料与性能意向表：尺寸来源、材质与维护需求、保留物品、接口依赖；目标尺寸和实测分开。
D05 讨论与决策记录：提出过的方案、否决方案、理由、分歧、谁确认、确认覆盖哪些字段与版本。
D06 待决策清单：缺失信息、问题的重要性、负责人、下一步验证动作。
D07 预算与范围：目标和硬上限分开；同币种、含税与安装等口径明确；示意分配不当报价。
D08 实施计划：下一步产物、输入依赖、负责人、评审点及阶段停止条件；没有现场资料不能给确定工期。
D09 风险与专业复核：测量、荷载、固定、结构、水电、材料证据、当地审批；用户同意不等于工程认证。
D10 可编辑文件及验证：真实 OpenPlan3D 原生 JSON + 业务 sidecar + 同版本截图/PDF；必须实际重新导入验收，不能用文件扩展名代替可编辑证明。

## 业主版：把被理解的感受变成可见的结果

U01 “我们听见了什么”：围绕其生活场景、纪念物品和难以表达的取舍做具体复述，不用泛化夸奖。
U02 全屋预期：空间功能分配、生活动线、统一的视觉方向；示意/概念/已核实模型状态明确。
U03 一天的生活场景：回家、用餐、工作、照护、休息如何被空间支持。
U04 细节参考卡：每图标注喜欢哪里、不复制哪里、对应需求、关键取舍、来源与下一步核实。
U05 决策与下一步：已清楚、仍可改变、最关键的少数决定；让业主知道自己仍有选择权。

## 质量门槛

正式值、AI建议、用户确认、专业核实分别管理。所有“已确认”都必须有确认主体、范围和版本；旧报告因新修改而过期，不覆盖旧版本。没有金额/币种/范围时，不产出看似正式的总报价。缺少尺寸或结构信息时仍可给概念 brief，但不能标记为可施工。

## 样例摘要（全部为虚构案例）

“一个可以慢慢长大的家”：两位成人、准备一个可调整的成长房，约90平方米仅作为背景假设。目标预算50,000 SGD、上限60,000 SGD是假设，不是市场报价。预算示意分配为基础工作18,000、固定柜10,000、活动家具8,000、家电5,000、灯光布艺4,000、未分配余量5,000；上限之内剩余额度不代表授权花费。

核心细节：客厅优先活动，不默认放中心茶几；保留有纪念意义的旧餐桌；宝宝用品按衣物、尿布、喂养用品、耗材四类整理，四类不等于四个柜子；卧室减弱工作干扰；灯光按活动场景讨论，不提前承诺具体照度或材料安全。

完整版附件有14条带来源需求、8张原创细节示意、6条标明虚构的对话证据、预算口径、决策记录、实施步骤与专业复核表。不是空模板，也不是本用户真实住宅的方案。
